# 既存ソースの受け渡し手順

## 受領するもの

- アプリ本体のソース
- READMEと起動・開発手順
- 依存関係ファイルとロックファイル
- 画像・アイコン等のアセット
- DBスキーマ、マイグレーション、権限ポリシー
- 実値を除いた `.env.example`
- テストコードと個人情報を含まないテストデータ
- 元リポジトリがある場合はURL、対象ブランチ・コミット、必要に応じてGit履歴
- 開発基準となる仕様書の原本

## 含めないもの

実APIキー、パスワード、認証トークン、秘密鍵、個人情報を含む本番DBデータは収録しません。`node_modules`、ビルド出力、キャッシュは通常不要です。

ZIPで受け取る場合はローカルで内容確認・展開してから、必要なソースファイルをGitに登録します。資料だけのZIPとアプリ本体のZIPは区別します。

## 受領後に確認すること

1. 既存README、設定、依存関係、技術スタックを読む。
2. 外部接続先と環境変数の参照を確認する。秘密値をログや資料へ出さない。
3. 現状のままローカル起動し、利用可能なbuild・lint・型チェック・既存テストを実行する。
4. 全画面、ルート、API、DB、認証、招待、家庭ごとの権限を調査する。
5. 実装済み・一部実装・未実装・不具合を、根拠を付けて分類する。
6. 仕様書との矛盾は両方の内容を示し、不明点を確定事項として扱わない。
7. 正常な機能と既存デザインを保持して、機能単位の修正計画を作る。

## Macからの自動保存

自動保存は未設定です。設定時には対象の作業フォルダ、送信先リポジトリ・ブランチ、Git認証、除外ファイルを確定します。競合時に強制プッシュで上書きする運用にはしません。

アプリを動かすためのAPI認証情報と、GitHubへコードを保存するためのGit認証は別です。認証情報はチャットやリポジトリへ記載しません。

GitHub Actionsも未設定です。ソース受領後、実際の検査コマンドに対応したワークフローを用意します。
